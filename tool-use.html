Tool Use：讓 AI 呼叫工具

LLM 不太會做的事，就不要再逼它了，交給工具。

為什麼需要工具

LLM 不擅長精確計算，也不知道你的實際資料，更不能自己上網。這些交給工具（函式）：精確計算、實際數據、網路搜尋。

兩個階段

以教材的飲料店為例，使用者說「我想訂 20 杯麥茶」：

使用者問題→① LLM 決定呼叫 quote_order("麥茶", 20)→Python 執行函式→回傳 JSON→② LLM 根據 JSON 回答
  1. LLM 先把自然語言轉成「工具名稱＋參數」。
  2. 程式執行函式，得到 JSON 結果；LLM 再依這份資料回答使用者。

JSON 基本上是用文字描述「有欄位名稱的資料表單」，電腦很喜歡處理這種格式。

{"ok": true, "item_name": "麥茶", "quantity": 20,
 "unit_price": 30, "total": 600, "stock": 30,
 "currency": "TWD", "ordered": false}

安全上的設計

  • 只允許事先寫好的工具名稱，不用 eval()。
  • 參數與型別由 Python 檢查，不合理的請求（例如 0 杯、不存在的品名）直接拒絕。
  • 缺資訊時請模型追問（clarify），不要猜參數。

工具不一定要自己寫

很多平台可以連結現成工具，例如上網搜尋、email、處理桌面檔案。教材提到兩個協定：MCP（Anthropic，與外部世界溝通）和 A2A（Google，Agent 之間溝通）。

重點：模型負責「理解並提出請求」，真正做事與計算的是程式；結果還要交回模型，才能產生給人看的回答。

我的作業實例

我用同樣的三階段架構做了一個「打工時數與收支小幫手」：說「昨天打了 4.5 小時」會呼叫記錄工時的函式，說「統整這個月」會由 Python 算出總工時、每週工時、收入與結餘，再由 LLM 整理成回答。工時乘時薪、加總與結餘都由 Python 計算，不讓 LLM 心算。
